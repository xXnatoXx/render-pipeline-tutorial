Texturing & Sampling

A texture is an image that the fragment shader looks up once per fragment. Most of the difference between a crisp image and a shimmering mess comes down to doing that lookup well: at the right spot, with the right amount of blur.

STEP 1Texels, UVs and unwrapping

A texture is a grid of colored cells called texels (texture elements), so they don't get mixed up with the pixels of the framebuffer. A 256×256 texture has 65,536 texels. On screen, one pixel might cover a tenth of a texel or a hundred texels, depending on how close the surface is.

Shaders don't address texels by integer index. They use UV coordinates: u runs across the image and v runs up it, both from 0 to 1. The same UVs then work whether the texture is 64² or 4096². Every vertex stores a UV pair as an attribute. The rasterizer interpolates it across the triangle (chapter 02), and the fragment shader uses it to sample the texture.

Where do the UVs come from? An artist (or a tool) unwraps the mesh: they cut it along seams and flatten the pieces into the UV square, the way a cardboard box unfolds into a flat net. Each flat piece is a UV island. Below, a cube unfolds into six islands.

texel coordinate: x = u·W − 0.5 y = (1 − v)·H − 0.5 texel i covers u ∈ [i/W, (i+1)/W]; its center sits at u = (i + 0.5)/W (v points up, OpenGL style: image row 0 is at v = 1. Direct3D puts v = 0 at the top.)

UVs are allowed to go outside 0…1, and the wrap mode (also called address mode) decides what happens there. Repeat keeps only the fractional part, so the texture tiles. That is how one small brick image covers a whole wall. Clamp to edge pins the coordinate to the border, which smears the edge texels outward. Mirrored repeat tiles too, but flips every other copy, so the seams always match up.

repeat: u' = u − floor(u) clamp: u' = min(max(u, 0), 1) (in texels: clamp the index to 0 … W−1) mirror: t = u mod 2; u' = t ≤ 1 ? t : 2 − t
Key idea. UVs connect a point on the surface to a point in the image, and they don't depend on resolution. Unwrapping chooses that mapping once. The wrap mode decides what happens beyond the 0…1 square.

STEP 2Affine vs perspective-correct interpolation

The rasterizer knows each fragment's screen-space barycentric weights b₀, b₁, b₂. The obvious move is to blend the vertex UVs with them: u = b₀u₀ + b₁u₁ + b₂u₂. This is called affine interpolation, and on a tilted surface it's wrong. Perspective squeezes far-away parts of a triangle into fewer pixels, so equal steps across the screen are not equal steps across the surface.

The fix comes from the perspective divide. After projection, u/w, v/w and 1/w do vary linearly across the screen (w is the clip-space w, which is the view depth). So the rasterizer interpolates those three values and divides once per fragment:

u = (b₀·u₀/w₀ + b₁·u₁/w₁ + b₂·u₂/w₂) / (b₀/w₀ + b₁/w₁ + b₂/w₂) example: halfway between a vertex at w = 1 (u = 0) and one at w = 3 (u = 1): affine u = 0.5 perspective u = (0.5·0 + 0.5·⅓) / (0.5·1 + 0.5·⅓) = 0.25

The original PlayStation's GPU did only affine texture mapping. You can see it in its games: textures bend along triangle diagonals and "swim" as the camera moves. Developers worked around it by cutting large polygons into many small ones, which keeps the error small.

Key idea. Interpolate attribute/w and 1/w linearly in screen space, then divide per fragment. Modern GPUs do this automatically for every varying. GLSL's noperspective qualifier is how you opt out.

STEP 3Magnification: nearest vs bilinear

When a surface is close, one texel covers many pixels. This is magnification. The sampler has to invent colors between texel centers, and it has two classic options.

Nearest (point sampling) returns the texel whose cell contains the sample point. You get hard, blocky texels, which is exactly what pixel-art games want. Bilinear finds the four texel centers around the sample point and blends them by distance: first along x, then along y.

x = u·W − 0.5 i = floor(x) fx = x − i y = (1−v)·H − 0.5 j = floor(y) fy = y − j color = (1−fx)(1−fy)·T[i,j] + fx(1−fy)·T[i+1,j] + (1−fx)·fy·T[i,j+1] + fx·fy·T[i+1,j+1] example: fx = 0.25, fy = 0.5 → weights 0.375, 0.125, 0.375, 0.125 (always sum to 1)
Key idea. Bilinear filtering hides the texel grid, but it can't add detail that isn't in the texture. Up close, a low-resolution texture just looks soft. That's why games use higher-resolution textures, layered "detail" textures, or nearest filtering on purpose for a pixel-art look.

STEP 4Minification, aliasing and mipmaps

The opposite case is worse. On a floor stretching to the horizon, one far-away pixel can cover dozens of texels. This is minification. A single point sample (even bilinear, which reads only 4 texels) picks one of those dozens almost at random. The result is aliasing: moiré patterns that don't exist in the texture, and shimmering that crawls across the surface as the camera moves. In sampling-theory terms, you need about two samples per cycle of detail (the Nyquist rate), and a distant checkerboard has far more detail than that.

The fix is to filter before sampling. Lance Williams' 1983 paper "Pyramidal Parametrics" introduced mipmaps (MIP stands for multum in parvo, "much in a small space"). A mipmap is a chain of copies, each half the width and height of the last, down to 1×1. Each texel of level k is the average of a 2×2 block from level k−1. The whole chain costs only one third more memory: 1 + ¼ + ¹⁄₁₆ + … = 4/3.

To pick a level, the GPU needs to know how many texels one pixel spans. It shades pixels in 2×2 quads, so it can subtract UVs between neighboring pixels to get screen-space derivatives. Shaders can read these too: ddx/ddy in HLSL, dFdx/dFdy in GLSL.

L = max( |∂uv/∂x|·size, |∂uv/∂y|·size ) texels per pixel λ = log₂(L) + bias mip level example: 256² texture, L = 4 texels/pixel → λ = 2 → level 2 (64×64) trilinear = lerp( bilinear(level ⌊λ⌋), bilinear(level ⌊λ⌋+1), λ − ⌊λ⌋ )

Bilinear filtering on one mip level leaves visible bands where λ crosses a whole number. Trilinear filtering removes them by also blending between the two nearest levels. The Mip tint mode paints each level a different color, a classic debug view for checking that texture resolution matches the screen.

Key idea. Never take one sample of a region that covers many texels. Mipmaps pre-average the texture, and screen-space derivatives choose the level whose texels are about one pixel in size.

STEP 5Anisotropic filtering

Map a square pixel onto a floor seen at a shallow angle and you get a long, thin shape in texture space. It might be 1 texel wide and 10 texels deep. A mip level can only filter a square region. If the GPU picks λ from the long side (as in step 4), it also blurs across the short side, and floors turn to mush in the distance. If it picks the short side, the long side aliases.

Anisotropic filtering takes several trilinear samples ("probes") along the footprint's long axis. Each probe uses a sharper mip level, chosen from the long side divided by the number of probes. The extension that introduced the setting, EXT_texture_filter_anisotropic, describes roughly this scheme. Real hardware algorithms are vendor-specific and not public in detail. The "2×…16×" option in game settings caps the number of probes.

Lmax = max(|ddx|, |ddy|) Lmin = min(|ddx|, |ddy|) (in texels) N = min( ceil(Lmax / Lmin), maxAniso ) λ = log₂(Lmax / N) color = average of N trilinear samples spread along the long axis example: |ddx| = 1.2, |ddy| = 9.6 → ratio 8 → N = 8, λ = log₂(1.2) ≈ 0.26 instead of 3.26
Key idea. A pixel's footprint in texture space is an ellipse, not a square. Anisotropic filtering covers the long axis with several small samples, so a floor stays sharp to the horizon without aliasing.

RECAPWhat to remember

  • Texels live in the texture and pixels live on screen. UVs in 0…1 link them independently of resolution. Unwrapping lays a mesh out as UV islands.
  • Wrap modes (repeat, clamp, mirror) decide what UVs outside 0…1 mean.
  • Interpolate u/w, v/w and 1/w, then divide: that's perspective-correct interpolation. Affine interpolation wobbles (PS1).
  • Magnification: nearest is blocky, bilinear blends 4 texels by distance.
  • Minification aliases. Mipmaps (Williams, 1983) pre-filter the texture, λ = log₂(texels per pixel) comes from ddx/ddy, and trilinear blends two levels.
  • Anisotropic filtering takes several probes along the long axis of an elongated footprint.

Textures hold more than color. Normal maps, roughness, metalness, ambient occlusion and height maps are all textures, and they go through the same sampler, mipmaps and filtering. (Filtering a normal map averages directions, which needs extra care in physically based shading; see chapter 07.) Real games also store most textures block-compressed, and the texture unit decodes them during sampling, which saves both memory and bandwidth:
