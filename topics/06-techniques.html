Chapter 06 · Modern techniques

Forward, Deferred & Shadows

A real game scene has hundreds of lights and needs shadows. This chapter is about organizing the fragment work so that the cost stays sane, and about the trick nearly every engine uses to decide what each light can actually see.

STEP 1The cost of many lights

In chapter 03 we lit a sphere with one light. The fragment shader looped over the lights and added up their contributions. This is forward rendering: each object is drawn and fully lit in the same pass, straight into the framebuffer.

The catch is how the cost grows. If the shader loops over every light, each fragment pays for every light, even ones on the far side of the level. Overdraw makes it worse: a fragment that is later hidden by a closer object was still fully lit. So the cost grows like fragments × lights, and the fragment count grows with the number of objects. Older engines often used multi-pass forward instead: draw each object once per light that touches it and add the results with additive blending. That avoids the "every light" loop, but you pay for the geometry again in every pass.

Deferred shading splits the work in two. A geometry pass stores surface data for the closest surface at each pixel. A lighting pass then shades each pixel once, using only the lights whose range reaches it. Tiled shading goes further: it cuts the screen into tiles of 16×16 or 32×32 pixels and builds a short light list for each tile.

Key idea. Shading cost should depend on how many lights actually touch a pixel, not on how many lights exist in the level. Every technique in this chapter is a way to get there.

STEP 2The G-buffer: shade later, from stored surfaces

The deferred geometry pass runs the vertex and fragment shaders as usual, but the fragment shader doesn't compute any lighting. It writes the material and geometry inputs to several render targets at once (multiple render targets, or MRT). Together these targets are called the G-buffer. A typical layout:

  • Albedo (base color), 8 bits per channel.
  • Normal: a direction in [−1, 1], packed into [0, 1] as n·0.5 + 0.5. That's why normal buffers look pastel: +X is reddish, +Y greenish, +Z bluish.
  • Roughness / metalness (chapter 07 covers these) and other material flags.
  • Depth: the normal depth buffer. The lighting pass rebuilds each pixel's 3D position from depth plus the pixel's screen coordinate.

The lighting pass then reads these textures. For each light it draws a light volume (a sphere mesh, or just a screen rectangle around it). Only pixels inside the volume run the lighting shader, and the results are added into an accumulation buffer with additive blending. Deferred shading has real costs. A 1080p G-buffer with four 32-bit targets plus depth is about 40 MB, written once and then read once per overlapping light, so memory bandwidth is the price. That hurts most on mobile GPUs. MSAA (chapter 07) is hard, because each G-buffer pixel would need several samples, and those samples would all have to be stored and lit. And the G-buffer keeps only one surface per pixel, so glass, smoke and other transparent things can't go through it. Deferred engines draw them afterwards in a separate forward pass.

Key idea. Deferred shading separates "what is at this pixel" from "how is it lit". Lighting cost becomes pixels × overlapping lights, no matter how many objects or how much overdraw there was. You pay for that in memory bandwidth.

STEP 3Forward+: tiled and clustered light culling

Drawing one volume per light still means reading the G-buffer again for each light. Tiled shading does the light culling up front instead. A compute pass splits the screen into tiles and tests every light's bounding sphere against every tile. The result is a short light list per tile. Shading then loops over that list only. This works for deferred (read the G-buffer once, loop over the tile's lights) and for forward, where it's called Forward+. Forward+ keeps the advantages of forward: MSAA works, transparency works, and there's no fat G-buffer.

A tile is really a long thin box that runs from the near plane to the far plane. A light hovering in front of a distant wall still lands in that wall's tile, even though it's nowhere near the wall in depth. Clustered shading also slices the view depth, usually with exponentially thicker slices further away, which gives a 3D grid of clusters. Each pixel looks up the cluster that matches its own depth.

Key idea. Cull once per tile or cluster, then shade from a short list. Tiles cut the screen in 2D. Clusters also cut along depth, so lists stay short even where near and far lights overlap on screen.

STEP 4Shadow mapping

Lighting so far treats every surface as if nothing stands between it and the light. To get shadows we need to know what the light can see. Lance Williams' 1978 answer is still the standard one: render the scene from the light's point of view, keeping only depth. The result is the shadow map. Later, in the main pass, each fragment is transformed into the light's space and compares its own distance to the light with the value stored in the map. If the fragment is farther away than the stored value, something closer blocks the light, so the fragment is in shadow.

This side view shows it in 2D. The light's "image" is one row of texels (the strip at the top). Each texel stores the distance to the first thing its ray hits.

Why acne? A texel covers a small wedge of directions, but it stores just one depth: the one along its centre ray. A ground point slightly off-centre lies a little farther away, so it "shadows itself". This happens in alternating bands, one per texel. Limited depth precision adds to it. The fix is a depth bias: subtract a small amount before comparing. Too much bias, and surfaces just behind an occluder's edge count as lit, so shadows lose contact with the objects that cast them. Engines combine a constant bias with a slope-scaled bias (more bias on surfaces seen at a grazing angle) and normal offsets.

A single comparison gives hard, blocky edges. Percentage-closer filtering (PCF) runs the comparison on several neighbouring texels and averages the yes/no results. You get a fraction between 0 and 1 and a softer edge. Note that PCF averages the results of the comparisons, not the depths themselves.

Key idea. A shadow map is a depth buffer rendered from the light. A fragment is in shadow if it is farther from the light than what the light saw. Bias trades acne against peter-panning, and PCF softens the edges.

STEP 5Cascaded shadow maps for the sun

The sun lights everything the camera can see, from your feet out to the horizon. One shadow map stretched over 100 m would make each texel tens of centimetres wide, which looks terrible up close. Cascaded shadow maps cut the view frustum into 3–4 depth ranges and give each range its own map. Near cascades cover a small area at high detail, far ones cover a big area at low detail. That roughly matches how much screen space things take up at each distance.

Where to split? Uniform splits waste resolution far away. Logarithmic splits match perspective in theory but make the first cascade tiny. The common "practical" scheme blends the two: dᵢ = λ·n·(f/n)^(i/N) + (1−λ)·(n + (f−n)·i/N).

Key idea. Spend shadow resolution where the camera needs it. Several maps, each fitted to one slice of the frustum, give sharp shadows nearby without wasting texels far away.

RECAPWhat to remember

  • Forward lights each fragment as it is drawn. Naively that costs fragments (with overdraw) × all lights. Multi-pass forward costs one geometry pass per light.
  • Deferred writes a G-buffer (albedo, normal, roughness/metal, depth) and then lights each pixel once per overlapping light volume. The prices: bandwidth, awkward MSAA, and a separate forward pass for transparency.
  • Forward+ / tiled builds per-tile light lists in a compute pass. Clustered also splits by depth. Both make shading cost scale with local light density.
  • Shadow mapping (Williams 1978): render depth from the light, then compare each fragment's light-space depth against it.
  • Too little bias causes acne, too much causes peter-panning. PCF averages several comparisons for soft edges. Cascades spread a sun's shadow resolution over the view distance.
